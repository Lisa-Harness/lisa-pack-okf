# lisa-pack-okf

Open Knowledge Format (OKF) v0.2 pack for [Lisa](https://github.com/Lisa-Harness/lisa).
Initialize, validate, ingest, emit, reindex, log, and export OKF bundles —
the vendor-neutral standard for representing knowledge as a directory of
markdown files with YAML frontmatter.

OKF is Google's open specification for representing knowledge as a directory
of markdown files with YAML frontmatter — human-readable, agent-parseable,
and version-controllable. This pack is the **interchange layer**: what you
ship, share, and version-control. It does **not** replace the memory backend
(SQLite); it is the format you export to and import from when you want
knowledge portable across tools, teams, or audits.

## What the pack does

Seven deterministic, no-LLM operations covering the full bundle lifecycle:

### Bundle lifecycle

| Operation | Purpose |
| --- | --- |
| `okf_init` | Scaffold a conformant bundle directory with `index.md` + `log.md` stubs under the `lisa-storage` sandbox. The `git init` for OKF bundles. Refuses non-empty bundles unless `force=True`. |
| `okf_reindex` | Walk the bundle via `lisa-storage`, regenerate `index.md` from current concepts, append a `reindex` entry to `log.md`. Preserves the existing index title unless overridden. |
| `okf_log` | Append a structured, timestamped entry to `log.md` via `lisa-storage` (read-rewrite). Low-level primitive used by `init`/`reindex` and exposed first-class for out-of-band events (reviewed, imported, exported). |

### Concept I/O

| Operation | Purpose |
| --- | --- |
| `okf_validate` | Check a bundle for OKF v0.2 conformance via `lisa-storage`. Strict mode additionally checks `status` enum, `stale_after` date format, `generated.at` presence, and `sources[].resource` shape. |
| `okf_ingest` | Read an OKF bundle via `lisa-storage` and return its concepts as structured data. Body truncation is opt-in via `truncate_body` (default `True` for backwards compatibility; pass `False` for full text). |
| `okf_emit_concept` | Write a single OKF concept document to a bundle directory via the `lisa-storage` MCP server's `write_file` tool. Accepts full provenance: `generated_by`, `resource`, `stale_after`, `status`, `tags`, `body`. |
| `okf_export_memory` | Export memory records to an OKF bundle. Calls `memory.list` to retrieve records, then writes each as a conformant concept document under `memories/` in the bundle via `lisa-storage` `write_file`. |

## OKF v0.2 quick reference

Every concept document requires:

- `type` (required) — the kind of concept (e.g. `Lisa Mode`, `Playbook`, `Metric`)
- `title` (recommended) — human-readable display name
- `description` (recommended) — one-line summary
- `tags` (recommended) — YAML list of categorization strings

Trust and provenance fields (all optional):

- `generated: { by, at }` — who produced the content and when
- `verified: [{ by, at }]` — who confirmed it
- `status: draft | stable | deprecated`
- `stale_after: YYYY-MM-DD`
- `sources: [{ id, resource, title, ... }]`

Reserved filenames:

- `index.md` — directory listing (regenerated by `okf_reindex`)
- `log.md` — update history (appended by `okf_log`, `okf_init`, `okf_reindex`)

Minimal concept example:

```markdown
---
type: Playbook
title: Deploy to staging
description: One-line summary of the deploy procedure.
tags: [deploy, staging]
generated: { by: human:adam, at: 2026-07-28T00:00:00Z }
status: stable
stale_after: 2026-12-31
sources:
  - id: runbook-1
    resource: https://wiki.example.com/runbooks/deploy
    title: Deploy Runbook
---
# Deploy to staging

Step-by-step body content in markdown.
```

## Requirements

- Python ≥ 3.11
- `pyyaml>=6.0` (declared in `pyproject.toml`)
- Lisa framework on `PYTHONPATH` (provides `kernel.models` and the
  operation execution context)
- A host that injects `ctx.execute_tool_fn` wired to the `lisa-storage`
  MCP server's `write_file` / `read_file` / `list_files` / `make_dir`
  tools. **All seven operations** route every read and write through
  `lisa-storage`; none touch the host filesystem directly. For
  `okf_export_memory` the host must also wire `memory.list`. Operations
  fail loudly if the tool executor is not injected.

## Installation

This pack is a git submodule of
[`lisa-packs`](https://github.com/Lisa-Harness/lisa-packs) and is consumed
as a path dependency by `../lisa/pyproject.toml`. Install it editable from
a checkout with submodules initialized:

```powershell
pip install -e ./okf
```

Or, from the `lisa-packs` monorepo root, install all packs:

```powershell
pip install -e ./okf -e ./compaction -e ./letta -e ./markdown -e ./mem0 -e ./search
```

The canonical interpreter for working on packs is the framework venv at
`../lisa/.venv`. Do not create a venv inside this pack.

## Enabling the pack

The pack registers itself through a single entry point in
`pyproject.toml`:

```toml
[project.entry-points."lisa.extensions.content_roots"]
okf = "lisa_packs.okf:get_content_root"
```

`get_content_root()` returns the pack's directory, which the host's
content-registry loader scans for the `OKF Mode` (`modes/okf/_mode.md`) and
the seven operation definitions under `operations/okf/*.yml`. No runtime
registration side effects; loading is side-effect-free on import.

### Selecting the OKF mode

The mode is routable on the `okf` keyword. Activate it by typing:

```plaintext
/okf validate my-bundle
/okf init my-bundle
/okf reindex my-bundle
/okf emit concept my-bundle modes/learn.md --type "Lisa Mode" --title "Learn"
```

The `command_pattern` is `^(?:(?:/)?(?:okf)(?:[\s,:;]+|(?=$)))(?P<query>.*)$`,
so both `/okf …` and `okf …` work.

### Operation availability

All seven operations ship with `default_available: true` and
`exportable: true` in their `.yml` metadata, so they are registered in the
operation catalog and exposed by default in every host that loads the pack.
The OKF mode declares `allowed_operation_ids` listing all seven, so the mode
restricts which operations the model can invoke while OKF mode is active.

## Configuration

There are **no environment variables, API keys, or secrets** to configure.
The pack has no MCP server of its own, no `mcp_servers.yaml`, and no external
service dependencies. All seven operations route every read and write through
the host's `lisa-storage` MCP server (`write_file`, `read_file`,
`list_files`, `make_dir`), sandboxed to the host's `data_dir/files` root.
The pack never touches the host filesystem directly.

- Read operations (`okf_validate`, `okf_ingest`) walk the bundle via
  `list_files` + `read_file`.
- Bundle lifecycle writes (`okf_init`, `okf_reindex`, `okf_log`) use
  `make_dir` + `write_file` (and `read_file` for `log.md` read-rewrite,
  since `lisa-storage` has no append primitive).
- Concept writes (`okf_emit_concept`, `okf_export_memory`) go through
  `write_file`.

### Path conventions

All operations take `bundle_path` as a **sandbox-relative path** under the
host's `data_dir/files` root (e.g. `okf/my-bundle`), never an absolute
filesystem path.

| Operation | `bundle_path` expects |
| --- | --- |
| `okf_init`, `okf_validate`, `okf_ingest`, `okf_reindex`, `okf_log`, `okf_emit_concept`, `okf_export_memory` | Relative path within the `lisa-storage` files sandbox (e.g. `okf/my-bundle`) |

Parent traversal (`..`) is rejected by every operation before the storage
server re-validates. Reserved filenames (`index.md`, `log.md`) cannot be
used as concept paths in `okf_emit_concept`.

## Operation reference

### `okf_init`

Scaffold a conformant OKF bundle directory.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox for the new bundle directory (e.g. `okf/my-bundle`). Created if missing. |
| `title` | str | `""` | Human-readable name for the bundle (written into `index.md`). |
| `description` | str | `""` | One-line description (written into `index.md`). |
| `force` | bool | `False` | Allow scaffolding into a non-empty bundle. |

Creates `index.md` (stub listing) and `log.md` (seeded with a `scaffold` entry).
Refuses a non-empty directory unless `force=True`.

### `okf_reindex`

Regenerate `index.md` from the bundle's current concepts.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox (e.g. `okf/my-bundle`). |
| `title` | str | `""` | Override title for `index.md`. If empty, keeps the existing index title or uses the bundle name. |

Walks the bundle, parses frontmatter from every non-reserved `.md` file,
writes a fresh `index.md` table of contents, and appends a `reindex` entry
to `log.md`.

### `okf_log`

Append a structured, timestamped entry to `log.md`.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox (e.g. `okf/my-bundle`). |
| `action` | str | required | Short verb (`reviewed`, `imported`, `exported`, …). |
| `concept_path` | str | `""` | Relative path of the affected concept, if any. |
| `by` | str | `lisa-pack-okf/0.1.0` | Actor string for the log entry. |
| `note` | str | `""` | Free-form one-line note. |

Creates `log.md` with a `# Bundle Log` heading if the file does not exist.

### `okf_validate`

Check a directory for OKF v0.2 conformance.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox (e.g. `okf/my-bundle`). |
| `strict` | bool | `False` | If `True`, additionally check `status` enum, `stale_after` date format, `generated.at` presence, `sources[].resource` shape, and `index.md`/`log.md` structure when present. |
| `include_strict` | bool | `False` | If `True`, strict violations also mark the bundle non-conformant. |

Returns an `OkfConformanceReport` JSON with `conformant`, `total_concepts`,
and `violations[]`. Non-strict conformance only fails on missing/unparseable
frontmatter or missing `type`; strict violations are reported separately and
only affect `conformant` when `include_strict=True`.

### `okf_ingest`

Read an OKF bundle and return its concepts as structured data.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox (e.g. `okf/my-bundle`). |
| `truncate_body` | bool | `True` | If `True`, truncate each concept body to 2000 chars. Pass `False` for full body text. |

Returns an `OkfBundle` JSON with a `concepts[]` list of `OkfConcept` objects
(`path`, `type`, `title`, `description`, `resource`, `tags`, `status`,
`generated_by`, `generated_at`, `body`).

### `okf_emit_concept`

Write a single OKF concept document to a bundle directory.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox. |
| `concept_path` | str | required | Relative path within the bundle (e.g. `modes/learn.md`). |
| `type` | str | required | The concept type (required OKF field). |
| `title` | str | `""` | Human-readable display name. |
| `description` | str | `""` | One-line summary. |
| `tags` | list[str] | `[]` | Categorization tags. |
| `status` | str | `stable` | Lifecycle status: `draft`, `stable`, or `deprecated`. |
| `generated_by` | str | `lisa-pack-okf/0.1.0` | Actor who produced the content. |
| `resource` | str | `""` | Canonical URI for the underlying asset. |
| `stale_after` | str | `""` | `YYYY-MM-DD` date after which the concept is stale. |
| `body` | str | `""` | Markdown body content. |

Writes through `lisa-storage` `write_file`; never touches the filesystem
directly. Rejects `index.md`/`log.md` as concept paths and `..` segments.

### `okf_export_memory`

Export memory records to an OKF v0.2 bundle.

| Parameter | Type | Default | Notes |
| --- | --- | --- | --- |
| `bundle_path` | str | required | Relative path within the `lisa-storage` files sandbox. Created if missing. |
| `limit` | int | `100` | Maximum number of memory records to export (1–1000). |

Calls `memory.list` to retrieve records, then writes each as a conformant
concept document under `memories/` in the bundle via `lisa-storage`
`write_file`. Derives `title` from the first ~60 chars of content, tags from
memory tier and operation id, and a metadata table in the body.

## Tests

The pack ships 20 tests in `lisa_packs/okf/tests/test_operations.py` covering
all seven operations, strict validation paths, ingest truncation on/off,
reindex title preservation/override, log append/create, and emit-concept

Run them against the framework venv:

```powershell
cd okf
$env:PYTHONPATH = "c:\Code\lisa;c:\Code\lisa-packs\okf"
```

## Design notes

- **No slice provider.** Indexing is explicit and on-demand (`okf_reindex`),
  not pressure-driven. A slice would only earn its place if OKF became a live
  working store; for the interchange use case, explicit reindex fits. The
  pattern is proven in the `compaction` and `letta` packs if a slice is ever
  needed.
- **Two I/O surfaces.** Read operations use `pathlib` directly (the bundle is
  on disk). Write operations go through the `lisa-storage` MCP sandbox so
  user-facing writes are isolated. The split is deliberate: validation and
  ingestion are safe to run against any path the process can read; emission
  and export produce user artifacts and must be sandboxed.
- **No external dependencies.** No MCP server, no `mcp_servers.yaml`, no API
  keys. The pack is pure local computation plus the framework-provided
  `lisa-storage` and `memory.list` tools.
